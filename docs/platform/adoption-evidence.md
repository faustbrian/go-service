## Structural concern disposition

| Frozen concern | Fixture evidence |
| --- | --- |
| commands, help, version | one `service.Definition` per service with standard and explicit custom commands |
| signals and repeated-signal policy | `service.Execute` owns cancellation and escalation; fixtures install no signal handler |
| exit codes and safe rendering | every role runs through the platform command result |
| management listener and probes | long-running definitions provide a separate `service.Management` listener |
| HTTP correlation | each definition accepts a caller-owned factory; realistic requests return distinct identities generated by that exact factory |
| startup, rollback, drain, shutdown, joins | explicit components and tasks run through the root lifecycle; role-isolation tests assert selected startup and reverse shutdown |
| configuration | typed loaders execute only for the selected command; Postal local dotenv uses `configservice` |
| logging and telemetry lifecycle | caller-owned facilities remain explicit components; Track compiles the telemetry adapter |
| infrastructure lifecycle | PostgreSQL, cache, Kafka, queue, scheduler, and migrations use their owning-module adapters |
| HTTP safety and timeouts | business HTTP is declared through `service.HTTP`; application routers remain caller-owned |

The fixtures contain no domain package, business payload ownership, schedule,
migration semantics, provider client, retry policy, service locator,
reflection-based registration, or mutable global state.

One-shot tests prove that Postal migration and Location migration, online
migration, and activation do not initialize unrelated long-running facilities.
Long-running role tests identify the exact selected plan, so swapping worker,
serve, or schedule plans fails the suite.

## Workload evidence

The acceptance suite sends deterministic Postal search, Track ingestion
fan-out, and Location lookup payloads through a real platform-owned HTTP
listener. It verifies response behavior and the canonical untrusted-ingress
correlation headers.

Five 200 ms microbenchmark samples on the frozen `darwin/arm64`, Apple M4 Max,
Go 1.26.5 environment produced:

| Workload | Time range | Bytes | Allocations |
| --- | ---: | ---: | ---: |
| Postal search | 2.308-2.345 us/op | 7565 B/op | 35 |
| Track ingestion fan-out | 3.311-3.361 us/op | 7717 B/op | 39 |
| Location lookup | 2.406-2.453 us/op | 7693 B/op | 44 |

These handler-shape measurements are not the required full process comparison.
Network p50/p95/p99 and throughput, startup probe latency, idle RSS, binary
size, and shutdown distributions remain Phase 6 evidence requirements and
must not be inferred from the microbenchmarks.
